# Boonma Taste — Mobile (Farm OS)

> Companion to `design-taste-frontend`. That skill is web-first (Tailwind/Motion/Next.js, landing pages).
> This one keeps its **thinking layer** — Design Read, Anti-Default Discipline, AI Tells, typography/color/materiality bias-correction — and replaces its **stack layer** with React Native reality.
> Scope: a Thai-first, outdoor, data-entry **product app**, not a marketing page. Read this before touching a screen.

---

## 0. THE DESIGN READ (already inferred — do not re-ask)

**Reading this as:** a farm-operations product app for hands-on operators (fish/shrimp ponds, feed, sell/move logs), used **outdoors on phones in bright sun**, Thai-first with Latin numerals, leaning toward a **calm, high-legibility, operational** language — closer to Linear/GOV.UK restraint than Awwwards.

Consequences that override generic taste:
- **Glanceable > expressive.** A tired operator reads this one-handed in the sun. Legibility and tap-target size beat cleverness every time.
- **Thai script is the constraint, not an afterthought.** Line-height and vertical rhythm must clear Thai marks/tone marks. See `[[project_thai_font_patched_metrics]]` — the patched IBM Plex Sans Thai is deliberate; never revert to stock.
- **`outdoor` mode is a first-class theme, not a gimmick.** Every screen must survive the `outdoor` palette (max contrast). If a design only looks good in `light`/`dark`, it's not done.

## 1. THE THREE DIALS (locked for this product)

* **`DESIGN_VARIANCE: 4`** — structured and learnable, with *intentional* focal moments (hero numbers, status). Not artsy chaos. Consistency is a feature in a tool people use daily.
* **`MOTION_INTENSITY: 3`** — motion is feedback and orientation only (sheet transitions, press states, value changes). No decorative/looping animation. Mid-range Android must stay 60fps.
* **`VISUAL_DENSITY: 6`** — informative but breathable. Operational data, but never cockpit-packed; outdoor glanceability caps density.

Override conversationally per screen (e.g. an onboarding/marketing surface can push VARIANCE up). Do not edit this file to override.

## 2. STACK (this app — non-negotiable)

* **Framework:** Expo + React Native + `expo-router`. No DOM. No `next/*`, no RSC, no `dark:` class variants, no `dvh`/`vh`, no Core Web Vitals.
* **Styling:** **NativeWind v4** (Tailwind classes) backed by `src/theme/tokens.ts` + `tokens.tailwind.cjs`. Style from tokens, never raw hex. Theme comes from `ThemeProvider` (`light` | `dark` | `outdoor`) — read the palette via the theme hook, don't hardcode a mode.
* **Animation:** `react-native-reanimated` v4 (worklets on the UI thread). This is the RN equivalent of the web skill's "never drive continuous values through React state" rule — use shared values, not `useState`, for gestures/scroll/press.
* **Sheets/gestures:** `@gorhom/bottom-sheet` + `react-native-gesture-handler` (already in use).
* **Safe area:** `ThemedSafeAreaView` / `react-native-safe-area-context`. This replaces the web skill's `min-h-[100dvh]` rule — never hardcode status-bar/home-indicator insets.
* **Fonts:** loaded via `src/theme/useAppFonts.ts`. **Dual family:** `IBMPlexSansThai_*` for text, **`IBMPlexSans_*` (Latin) for numbers/data** (`type.familyNum*`). Numeric-heavy cells (weights, prices, counts) use the Latin numeric family for tabular alignment.
* **Icons:** the project's existing icon set. One family, consistent stroke weight. Never hand-roll SVG paths for a glyph that exists.
* **Dependency check:** before importing any lib, confirm it's in `mobile/package.json`; if missing, surface the install command first.

## 3. TOKENS ARE THE SOURCE OF TRUTH — `src/theme/tokens.ts`

Do not invent colors, spacing, or radii. Pull from tokens:
- **Spacing:** `space` — 4px grid (`4 8 12 16 20 24 32 40 48 64`). Pick from the scale; no arbitrary `padding: 13`.
- **Radii:** `radii` — `xs6 sm10 md14 lg18 xl24 pill`. One radius family per surface level; don't mix.
- **Type scale:** `type.sizes` — `xs11 sm13 base15 md16 lg18 xl22 xxl28 hero34`. Real hierarchy = jumping the scale (e.g. `hero34` next to `sm13` label), not nudging 15→16.
- **Semantic action colors** (this is the app's signature — respect the meaning):
  - `fill` = green (add / intake / buy-in)
  - `move` = blue (transfer / relocate)
  - `sell` = purple (sell / outflow)
  - `brand` = teal (identity / neutral primary)
  - plus `warn` / `danger` / `success` / `statusActive` / `statusMaint`, each with a `*Soft` background and `*Ink` on-color.
  Never use a raw green/blue/purple that isn't one of these — the color *is* the meaning here.
- **Elevation:** use `shadow` / `shadowLg` tokens (or a token-driven RN shadow helper). Don't scatter ad-hoc shadow objects.

## 4. ANTI-SLOP DIRECTIVES (ported from design-taste-frontend §0.D, §4, §9 → RN)

Read the web skill's §0.D (Anti-Default), §4 (Bias Correction), and §9 (AI Tells) for the full reasoning. In RN terms, the rules that actually catch slop:

**Typography**
- Real hierarchy comes from **scale jumps + weight**, not color alone. A screen where everything is `base15` in three greys is slop.
- Emphasis stays in the **same family** — use `familyBold`/`familySemi`, never swap to a decorative face mid-headline.
- Thai body needs generous `lineHeight` (≈1.5–1.6× size) so marks don't clip; don't reuse a tight Latin line-height on Thai.

**Layout & spacing**
- Space from the `space` scale only. Consistent rhythm > pixel-nudged one-offs. The #1 mobile slop tell is uneven, arbitrary gaps.
- Escape the "stack of identical rounded cards" default. Vary surface hierarchy (`surface` / `surfaceAlt` / `surfaceSunk`) and give the primary object of a screen real weight; don't render every row as the same card.
- Tap targets ≥ 44pt. Non-negotiable — this is a gloves-in-the-sun app.

**Color & materiality**
- Neutral-forward. Color is reserved for **meaning** (the semantic actions) and status — not decoration. No gradient-for-the-sake-of-it, no AI-purple wash.
- Backgrounds are the warm off-white / true-dark tokens, never pure `#fff`/`#000` invented on the spot (except where `outdoor` mode intends max contrast).

**Motion (Reanimated)**
- Motion must mean something: confirm an action, orient a transition, reflect a value change. Duration 150–250ms, standard easing. No infinite loops, no parallax, no decorative float.
- Respect `AccessibilityInfo.isReduceMotionEnabled` — gate non-essential animation off it.

**Content & the "Jane Doe" tell**
- No lorem, no `฿0.00` / `123` placeholder rows shipped as if real. Empty states are designed states with a real next action — not a sad centered icon + "No data".
- **No emoji as UI** (icons instead) unless a surface is explicitly playful.

## 5. REDESIGN PROTOCOL (for existing screens — audit first)

When improving an existing screen (see the `redesign-existing-projects` skill for the general audit method):
1. **Audit before overhaul.** Read the screen, name the top 3 concrete slop/legibility problems (weak hierarchy? arbitrary spacing? color misuse? cramped Thai?). State them before editing.
2. **Preserve behavior & data flow.** Restyle; don't silently change logic, navigation, or state. Read `[[feedback_no_fallback_user]]` — no mock/fallback data introduced during a redesign.
3. **Reuse tokens & existing components** (`src/components/ui/*`, `ThemedSafeAreaView`, existing sheets) before creating new primitives.
4. Follow `[[feedback_no_auto_commit]]` — implement, summarize, stop. Never commit/push.

## 6. PRE-FLIGHT CHECKLIST (before saying a screen is done)

- [ ] Renders correctly in **all three** themes: `light`, `dark`, **`outdoor`**.
- [ ] All color, spacing, radii, type sourced from `tokens.ts` — zero raw hex / magic numbers.
- [ ] Numbers use the Latin numeric font family; Thai text has mark-safe line-height.
- [ ] Hierarchy reads at a glance in sunlight — clear primary/secondary/tertiary.
- [ ] Tap targets ≥ 44pt; safe-area insets via `ThemedSafeAreaView`, not hardcoded.
- [ ] Motion (if any) is purposeful, ≤250ms, and honors reduce-motion.
- [ ] Empty/loading/error states designed, not afterthoughts. No placeholder data shipped.
- [ ] Dials respected: VARIANCE 4 / MOTION 3 / DENSITY 6 (or the agreed per-screen override).
